---

## 1. Executive Summary & Purpose

Module 1 provides the entry point for academic credential ingestion and record management in the ChainCert system. It handles certificate record creation, parsing plain text certificate files (`.txt`), validating required academic metadata fields, storing structured records in an SQLite database, and handing off validated dictionary payloads to Module 2 (Hashing Engine) to obtain authoritative SHA-256 fingerprints.

---

## 2. Certificate Fields & Canonical Order

Module 1 strictly adheres to Module 2's canonical field ordering to maintain Single Source of Truth (SSoT) compatibility across all downstream modules.

| Field Name | Type | Constraints / Normalization Rules | Description |
| :--- | :--- | :--- | :--- |
| `certificate_id` | `str` | Unique non-empty string | Primary academic credential identifier |
| `student_name` | `str` | Non-empty string | Full student name |
| `roll_number` | `str` | Non-empty string | Student roll number |
| `course` | `str` | Non-empty string | Academic degree/branch |
| `cgpa` | `str` / `float` | Float $[0.00, 10.00]$ | Cumulative Grade Point Average |
| `issue_date` | `str` | ISO format `YYYY-MM-DD` | Date certificate was issued |
| `institution_id` | `str` | Non-empty string | Institutional identifier |

### Additional Database Metadata Fields
- `status`: `REGISTERED` | `BATCHED` | `CHAINED`
- `canonical_data`: Canonical UTF-8 pipe-delimited string generated by Module 2.
- `certificate_hash`: 64-character hexadecimal SHA-256 digest generated by Module 2.
- `batch_id`: Associated batch ID (e.g. `SEM1_2026`).
- `merkle_root`: Merkle Root generated by Module 3 for the batch.
- `merkle_proof`: JSON text containing O(log N) Merkle proof steps.
- `created_at` / `updated_at`: UTC timestamps.

## 3. Plain Text File Parser (`records/parser.py`)

For Review 2, input is accepted in key-value `.txt` file format:

```txt
CERTIFICATE ID: CC001
NAME: Rahul Sharma
ROLL NUMBER: A101
COURSE: AI & DS
CGPA: 9.20
ISSUE DATE: 2026-08-20
INSTITUTION ID: MMCOE
```

`parse_certificate_text()` maps key aliases (e.g., `STUDENT NAME` $\rightarrow$ `student_name`, `ROLL NO` $\rightarrow$ `roll_number`) to standard canonical field names and validates presence and data types.

## 4. SQLite Database Schema (`records/database.py`)

```sql
CREATE TABLE IF NOT EXISTS certificates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    certificate_id TEXT UNIQUE NOT NULL,
    student_name TEXT NOT NULL,
    roll_number TEXT NOT NULL,
    course TEXT NOT NULL,
    cgpa TEXT NOT NULL,
    issue_date TEXT NOT NULL,
    institution_id TEXT NOT NULL,
    status TEXT DEFAULT 'REGISTERED',
    canonical_data TEXT,
    certificate_hash TEXT,
    batch_id TEXT,
    merkle_root TEXT,
    merkle_proof TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS batches (
    batch_id TEXT PRIMARY KEY,
    certificate_count INTEGER NOT NULL,
    merkle_root TEXT NOT NULL,
    block_id INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 5. Module 1 $\rightarrow$ Module 2 Hand-off

```python
from chaincert.records import add_certificate

# 1. Parse text file
cert_dict = parse_certificate_file("test_certificates/certificate1.txt")

# 2. Add certificate (automatically invokes Module 2 hash_certificate)
record = add_certificate(cert_dict)

# 3. record contains certificate_hash and canonical_data from Module 2
```
